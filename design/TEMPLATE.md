## 1. 目标与非目标

### 1.1 目标

用可验证的句子描述这个模块要解决的问题，例如：

- 提供从 Chat Completions 请求到 XIR `Request` 的无损解码；
- 对 1 MiB 请求的 envelope 扫描不分配超过 N 次；
- 让外部 Go 程序可以只 import 本包完成 X 能力。

### 1.2 非目标

明确写出本模块不负责的事，防止职责膨胀。例如：

- 不做路由选择；
- 不读写数据库；
- 不实现流式转换；
- 不承诺覆盖厂商私有字段。

## 2. 当前实现与约束

- 现有代码位置和行为；
- 现有测试、fixture、benchmark；
- 兼容性约束（cassette、replay、API、数据库）；
- 已知 bug / 技术债；
- 迁移期间必须保持的行为。

涉及现有文件时给出相对链接，例如 [`internal/proxy/handler.go`](../internal/proxy/handler.go)。

## 3. 对外契约（`pkg`）

### 3.1 包结构

```text
pkg/example/
  example.go
  internal/...   // 如需要，保持实现细节不可见
```

### 3.2 Go API

给出真实可编译的签名，而不是伪代码。至少包括：

- 构造函数；
- 核心方法；
- 错误类型/诊断类型；
- 选项结构；
- 并发安全说明。

```go
package example

type Options struct {
    // ...
}

type Result struct {
    // ...
}

func New(opts Options) (*Service, error)

func (s *Service) Do(ctx context.Context, input Input) (Result, error)
```

### 3.3 错误与诊断

| 错误/诊断 | 触发条件 | 调用方应如何处理 |
| --- | --- | --- |
| | | |

约定：

- 不使用字符串匹配判断错误类型；
- 可恢复的局部问题用诊断，不可恢复的用 error；
- error 带上下文，但不包含敏感值。

### 3.4 并发、生命周期、资源

- 是否并发安全；
- 是否持有 goroutine / 连接 / 文件；
- 谁负责 Close；
- 超时和取消如何传播。

## 4. `internal` 集成

- 哪些 internal 包会使用本模块；
- 依赖注入方式（构造参数、接口、全局 registry？优先显式注入）；
- 在热路径还是审计路径；
- 配置从哪里来；
- 失败时如何降级；
- feature flag 名称和默认值。

```text
internal/gateway ──uses──▶ pkg/example
internal/audit   ──uses──▶ pkg/example
```

## 5. 数据模型与格式

### 5.1 类型

列出核心结构体/字段，说明零值语义和可选性。

### 5.2 序列化

- JSON 字段名、omitempty、未知字段处理；
- 是否进入 cassette / DB / API；
- 版本兼容。

### 5.3 配置

```yaml
example:
  enabled: true
  timeout_ms: 5
```

说明默认值、校验规则、热更新是否生效。

### 5.4 数据放置

说明本模块产生的数据放在哪里：

| 数据 | 文件 / DB / 内存 | 理由 | 丢失后果 |
| --- | --- | --- | --- |
| | | | |

必须回答：

- 哪些是事实源，哪些是派生；
- 是否会写 cassette；如果会，是原始字节还是摘要；
- 是否写 DB；表名和迁移；
- 哪些只在内存，重启后如何重建；
- 保留期、清理、重建方式。

默认原则见 [数据放置与证据模型](./02-data-placement.md)：文件只存 raw HTTP + 最小 meta；路由/usage/摘要进 DB；运行态进内存。

## 6. 算法与不变量

### 6.1 算法

用步骤或伪代码描述关键算法。必须说明复杂度和最坏情况。

### 6.2 不变量

例如：

- 同协议转换永远字节直通；
- 改写后的 `Content-Length` 必须等于实际 body 长度；
- mask 假值长度必须等于真值；
- 任何一个 finding 必须能定位到 span。

### 6.3 边界条件

- 空 body、超大 body、非法 JSON、截断 SSE；
- 重复字段、未知字段、转义字符；
- 并发请求、取消、超时；
- 上游提前关闭。

## 7. 失败语义

| 场景 | 行为 | 是否影响上游健康 | 客户端看到什么 |
| --- | --- | --- | --- |
| 输入非法 | | | |
| 转换不支持 | | | |
| 上游 4xx/5xx | | | |
| 超时/取消 | | | |
| 内部 panic/bug | | | |

明确 fail-open / fail-closed。

## 8. 性能

- 热路径/审计路径；
- 每请求额外分配、复制、解析次数；
- 目标 p50/p99 或相对基线；
- benchmark 命令和结果记录方式；
- 大 body / 流式场景的内存上限。

## 9. 安全

- 凭据、PII、敏感值是否进入日志/DB/cassette；
- 是否执行外部输入（路径、命令、URL）；
- SSRF、路径穿越、注入风险；
- 权限与审计要求。

## 10. 可观测性

- 指标（名称、类型、标签）；
- 事件（DB 事件；cassette event 默认不写）；
- 日志级别与脱敏；
- 排障入口。

## 11. 测试与验收

### 11.1 单元测试

- 表驱动用例；
- 错误路径；
- 并发/race；
- fuzz。

### 11.2 集成测试

- 与哪些包联调；
- 使用哪些 cassette/fixture；
- 是否需要网络（默认不允许）。

### 11.3 差分测试

- 与旧实现对比什么（字节、决策、usage、findings）；
- 允许的差异及理由。

### 11.4 验收标准

可勾选清单：

- [ ] 公开 API 有文档和示例；
- [ ] 离线测试通过；
- [ ] benchmark 达到预算；
- [ ] 热路径字节保真；
- [ ] 文件/DB/内存边界明确，未把路由/usage 写进 cassette；
- [ ] 失败语义有测试；
- [ ] 文档同步。

- 旧代码删除条件。

## 14. 实施拆分

把模块拆成可独立提交的步骤：

1. 类型与接口；
2. 核心实现；
3. 测试/fixture；
4. internal 接入；
5. 清理。
